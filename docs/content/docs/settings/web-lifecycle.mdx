## 1. Lock on Launch

When enabled, the app will immediately enter locked/pinned mode
on startup, preventing exit until unpinned.

On some devices, you may still be prompted with a confirmation screen.

**Default:** false

### 1.1. Re-lock After Unexpected Exit

**Settings → Web Lifecycle → Re-lock After Unexpected Exit**

When **Lock on Launch** is enabled and {APP_NAME} is the **Device Owner**,
this option periodically checks whether full lock task mode has unexpectedly
ended while the kiosk activity is on screen. If Android ends the lock without
the app's Unlock action, the app attempts to lock again automatically.

This can help on devices where manufacturer firmware unexpectedly exits kiosk
mode, for example after a hardware Back-button gesture. It does not stop the
underlying firmware behaviour or guarantee recovery if the app is no longer in
the foreground. Recovery is armed only after a full managed lock has been
observed. Screen pinning and unsuccessful initial locks are not covered.

Requires Android 7.0 or newer, Device Owner, and lock task allowlisting.
The app retries failed attempts with a delay to avoid repeated locking prompts.
Turning this option or Lock on Launch off clears the previous lock observation,
so enabling it again cannot recover an older exit.

**Setting key:** `web_lifecycle.relock_on_unexpected_exit`

**Default:** false

## 2. Reset on Launch

When enabled, the app will always start fresh at the Home URL when
closed and re-opened, as opposed to the last visited URL.

The navigation history will also be cleared.

**Default:** false

## 3. Reset On Inactivity (seconds)

Number of seconds of inactivity before the app resets to the home URL.

When there is 5 seconds left, a warning countdown will be shown on
the screen. User interactions with the screen reset the timer.

The navigation history is cleared when `History` is selected under
`Reset Actions` (enabled by default).

To disable, use the value `0`.

**Minimum:** 10

**Default:** 0

## 4. Reset Actions

Choose which browsing data to clear when the inactivity timer resets the app
to the Home URL. Use `Add` to select more actions, remove any unwanted actions,
or drag the handle at the end of a row to rearrange them.

The app returns to the Home URL even if no actions are selected.

| Action           | Description |
|------------------|-------------|
| History          | Clears the browsing history and back/forward navigation history. |
| Cookies          | Removes all WebView cookies, including login sessions. |
| Web Storage      | Deletes HTML5 website storage, including localStorage and IndexedDB. |
| Cache            | Clears cached website resources from disk. |
| Form Data        | Clears saved WebView form entries on older Android versions. |
| SSL Preferences  | Clears remembered SSL certificate decisions. |
| Recreate WebView | Replaces the current WebView to end the in-memory page session. |

<Callout title="Form Data" type="warning">

This action does not remove saved entries from Android's autofill service.

</Callout>

Selected cleanup actions run in the configured order. `Recreate WebView`
always runs after the other actions, before loading the Home URL.

Cookies and Web Storage are shared across websites in the app. Clearing them
may sign you out of multiple websites. App settings, bookmarks, and local files
are not removed.

**Default:**

```
["HISTORY"]
```

## 5. Dim Screen On Inactivity (seconds)

Number of seconds of inactivity before the screen is dimmed (brightness = 0).

This will set the app brightness to 0, and will restore the brightness to
your `device -> brightness` setting upon new user interactions.

**Minimum:** 10

**Default:** 0

## 6. Refresh on Network Available

Select when the page should automatically refresh when network connectivity
is restored.

- **Always:** refresh whenever a network connection is available
- **On Page Error:** only refresh if the previous page load failed
- **Never:** do not refresh automatically

**Default:** On Page Error

## 7. Refresh on Loading Error Interval (seconds)

Interval in seconds between automatic refresh attempts when a page fails
to load. This usually indicates a connection failure, such as when the
device is offline or the server is unavailable. On Android 6 and newer,
main-page HTTP 5xx responses (such as 500, 502 and 503) also trigger retries.
HTTP 4xx responses, including 401, 403 and 404, do not trigger retries.
Failed images, scripts and iframes do not trigger a page refresh.

This is detected using the Android API:
[WebViewClient#onReceivedError](https://developer.android.com/reference/android/webkit/WebViewClient#onReceivedError(android.webkit.WebView,%20android.webkit.WebResourceRequest,%20android.webkit.WebResourceError))
in conjunction with
[WebResourceRequest#isForMainFrame](https://developer.android.com/reference/android/webkit/WebResourceRequest#isForMainFrame()).
HTTP server errors are detected using
[WebViewClient#onReceivedHttpError](https://developer.android.com/reference/android/webkit/WebViewClient#onReceivedHttpError(android.webkit.WebView,%20android.webkit.WebResourceRequest,%20android.webkit.WebResourceResponse)).
These errors also count as page errors for `Refresh on Network Available`.

Retries honour URL restrictions. The server's response remains visible until the
next attempt. A successful new load or navigation to another page clears the
error. On Android 5, connection-error recovery continues to work, but HTTP status
recovery is unavailable.

To disable, use the value `0`.

**Minimum:** 5

**Default:** 0

## 8. Refresh on Screen Wake

Refresh the current page once when the device wakes from sleep.
The kiosk page must be in the foreground before and after sleep.

**Default:** false
