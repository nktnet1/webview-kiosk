## Setup

<Steps>

<Step>
Configure Home Assistant's
[MQTT integration](https://www.home-assistant.io/integrations/mqtt/).
</Step>

<Step>
Enable **MQTT** in {APP_NAME}, and configure **MQTT → Connection** to use the
same broker.
</Step>

<Step>

Open **MQTT → Home Assistant**, turn on **Enable Discovery**, and optionally
enter a **Device Name**.

</Step>

<Step>
Connect or restart MQTT using the controls on that screen.
</Step>

<Step>
Find the kiosk under Home Assistant's **Settings → Devices & services → MQTT**.
</Step>

</Steps>

The kiosk appears as one device containing its controls, settings, and sensors.
For background monitoring, enable **MQTT → Use Foreground Service** and follow
the [battery optimisation guidance](/docs/settings/mqtt#52-use-foreground-service).

## Controls

| Control | What it does |
| --- | --- |
| Go home, Go back, Go forward, Refresh | Navigate or reload the current page |
| Go to URL, Search | Open a URL or search for the entered text |
| Page up, Page down, Go to top, Go to bottom | Scroll the page |
| Clear history, Clear cache | Clear the selected WebView data |
| Kiosk lock | Lock or unlock the app's kiosk mode |
| Lock device | Lock Android - requires device owner permission |
| Launch package | Open the entered Android package name |
| Toast | Show the entered text as a brief Android popup |
| Notification | Show the entered text as an Android notification |
| Reconnect MQTT | Restart the kiosk's MQTT connection |

Saving a command text field sends its value to the kiosk. **Go to URL** shows the
current URL when it fits within the 255-character input limit. The other command
text fields start blank and clear when the kiosk next updates its state.

Navigation needs an active WebView. Notifications require both the app's
notification setting and Android notification permission.

## App settings

Each configurable app setting has a corresponding Home Assistant control:

| Setting type | Control |
| --- | --- |
| On/off | Switch |
| Integer | Number within the supported range |
| Choice | Dropdown |
| Text | Text input |
| Ordered action list | Text input containing an array, such as `["HISTORY","CACHE"]` |
| Password | Write-only password input |

Changes use the same validation and permissions as the app.
Administrator-managed settings are shown but unavailable for editing. After
changing MQTT connection or discovery settings, use **Reconnect MQTT**.
Changing credentials or disabling MQTT can interrupt remote access.

Text inputs accept up to 255 characters. Longer existing values leave the input
blank. The full non-password value is available in the entity's `value`
attribute. Edit longer values in the app. Saving a text or list setting
replaces its entire value.

Password inputs always stay blank. They can replace or clear a password, but
passwords are never included in the reported settings or request results.

## Status and refresh buttons

Sensors show battery percentage, current URL, screen state, kiosk lock, lock
type, last interaction, app brightness, and system brightness. The current URL
sensor also exposes the full URL in its `url` attribute.

State updates when MQTT connects, when Home Assistant restarts, and every 30
seconds while connected. URL, screen, and kiosk lock changes update
immediately. App brightness can show `-1` when no activity window is available;
system brightness uses Android's 0--255 scale.

Use the **Refresh** buttons to fetch additional information:

| Button | Result |
| --- | --- |
| Refresh Status | Current kiosk status; also updates the status sensors |
| Refresh Settings | Current app settings; also updates the setting controls |
| Refresh System info | App and Android device information |
| Refresh Launchable packages | Packages that Android can launch |
| Refresh permitted launchable packages | Launchable packages permitted in lock-task mode |
| Refresh Lock task packages | Permitted lock-task package names; Android 8 and later |

Each result sensor shows when the result was last updated. Open its attributes to
see the returned data. Results remain unknown until the corresponding refresh
button is used. Failed requests include an `error` attribute.

An unknown **Request error** value is normal until an invalid request is received.

## Discovery settings

| Setting | Default | Purpose |
| --- | --- | --- |
| Enable Discovery | Off | Make the kiosk available in Home Assistant |
| Device Name | Automatic | Optional display name; renaming preserves existing entities and automations |
| Discovery Prefix | `homeassistant` | Match Home Assistant's MQTT discovery prefix |
| Status Topic | `homeassistant/status` | Match Home Assistant's MQTT birth/status topic |

Leave the prefix and status topic at their defaults unless Home Assistant uses
custom values. Each setting has an info icon for further help. Reconnect MQTT
after changing discovery settings.

Discovery manages the kiosk's online/offline status, including unexpected
connection loss. Custom settings under **MQTT → Will** apply when discovery is
disabled.

## Troubleshooting

- **Device missing:** check that both systems use the same broker, MQTT discovery
  is enabled in Home Assistant, and the discovery prefixes match. Restart the
  kiosk's MQTT connection and check **MQTT → Debug Logs** for failures.
- **Entities disabled:** open Home Assistant's **Settings → Devices & services →
  Entities**, filter to the kiosk, and enable the desired entities. Check the MQTT
  integration's **Enable newly added entities** preference. Home Assistant keeps
  your saved enable/disable choices when discovery updates.
- **Controls unavailable:** reconnect MQTT. Individual configuration controls also
  remain unavailable while an administrator manages that setting.
- **Result unknown:** press its corresponding **Refresh** button.
- **Removing the device:** disable discovery and reconnect to the same broker so
  the kiosk can remove its discovery entry. If you changed brokers, reconnect to
  the old broker to remove its old entry.

If your broker restricts topics, allow the kiosk and Home Assistant to use the
configured discovery prefix, the configured status topic, and
`wk/<app-instance-id>/ha/#` for kiosk state and controls.
