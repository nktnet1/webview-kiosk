---
title: Troubleshooting
description: Resolve ownership, permission, and startup problems.
---

Start with **Settings → Device → Manage Device Policies**. No owner permission
is a normal state before activation; it does not mean the app is broken.

## Common problems [#common-problems]

| Problem | What to do |
| --- | --- |
| Shizuku is not running or disconnected | Open Shizuku, start its service, then retry. On Android 6–10 without root, use its computer startup method; wireless startup needs Android 11+. |
| Permission denied | Allow {APP_NAME} in Shizuku or Dhizuku. A device restriction may still prevent the requested operation. |
| No device owner is configured | Activate Device Owner, choose main-user Profile Owner, or ask your existing DPC to allowlist the kiosk. Starting Shizuku or installing Dhizuku alone does not grant ownership. |
| Accounts block activation | Review conflicting accounts. The optional account workaround is attempted only on Android 12+ and may fail. Use a backed-up, factory-reset device with QR setup if necessary. |
| Another owner already exists | Check the existing management app. Use its allowlist or shared permissions instead of trying to install a second Device Owner. |
| Other users or profiles block activation | Review Android's users and profiles. Removing one deletes its data, so back it up before deciding to remove it. |
| Wrong user | Open the app in the main user, usually ID `0`. On Android 14+, check with `adb shell cmd user get-main-user`. Do not substitute the current foreground user blindly. |
| Administrator not found | Check that the app is installed in the intended user and that your ADB command matches its installation source. |
| Dhizuku not detected | Open Dhizuku and confirm it has been activated in the same user, then reopen Device Policies. This integration requires Android 9+. |
| Owner role appears but Lock Task controls are unavailable | Read the reason shown beside the control. Work-profile scope, Android version, or insufficient policy authority can prevent access. |
| Activation timed out | Check Device Policies before retrying, because Android may already have granted ownership. Keep Shizuku running during activation. |

## Setup-state recovery [#setup-state-recovery]

If the result specifically says that the original setup state could not be
restored, keep Shizuku running and stop retrying activation. Connect ADB and run
the following command, replacing `0` with your main user ID if different:

```sh
adb shell settings --user 0 put secure user_setup_complete 1
```

Restart the device, then check Device Policies. If Android refuses this recovery
command, get help from your device administrator before continuing.
